# 机器人数据基础设施报告

两个视角使用同一版本 `model.js`（2.2.0），不维护两套互相矛盾的单价和费用函数。V2 的三个方案也直接调用详细版的逐日模拟。

| 入口 | 面向对象 | 口径 |
|---|---|---|
| [index.html](index.html) | 技术、财务、采购 | 按日库存推演，默认 36 个 30 天月份，现金与折旧分列 |
| [v2.html](v2.html) | 管理层 | 五个业务变量（按小时）、三个固定方案；36 个月总成本、每交付小时成本与追加投资分列 |

没有 CDN、外部字体、后端或遥测。将目录完整保存后可使用；也可生成两个独立 HTML：

```sh
python3 build.py --out dist
# dist/index.html 和 dist/v2.html 可单独打开；放在一起可互相跳转。
```

## 2.2.0 更新

- **V2 改为按采集小时输入**：每日采集小时数、每月交付小时数；小时按详细版模态结构折算体积。头部展示"基础设施费 / 交付小时"。
- **可交付数据默认长期保留**：2.1.0 的"成品保留 30 天"是误解。可交付数据会被反复出售，默认长期放在低频档；保留期作为业务变量（长期 / 1 年 / 30 天）。原始数据保留也可选（永久 / 1 年 / 90 天），永久保留时满 1 年转深度归档。
- **V2 三方案直接调用 `simulate()`**：A 全云标准、B 全云分层、C 机房窗口 + 云归档。主数字为 36 个月总成本（费用 + 折旧），第 12 个月月费、每交付小时成本和追加设备投入分列。C 标注"含占位报价"。A、B 不使用机房，因此不计已有机房运营费。
- **机房滚动窗口**：`idcWindowDays()` 由已有可用容量、采购余量、留存比例和日产量推算窗口天数；V2 默认已有容量 100 PB（约 83 天）。详细版新增"机房窗口 + 云归档"预设。
- **阅读辅助**（`content.js`）：设计原则、名词解释、点击 ? 弹出的一句话定义，以及每个参数的来源标签（已查实 / 估计 / 占位 / 待确认）。
- 详细版界面用语"成品"统一为"可交付数据"。

## 2.1.0 修正

- 用每日均匀新增的容量时间积分计费，月末库存只用于容量显示和资源需求；历史流入不再被当前增速覆盖。
- 明确数据年龄与最终删除期，验证 `lagDays <= hotDays <= stdDays <= arcDays`。原始留存比例不再绕过热缓冲；原始、成品库存可有限保留。
- 用实际转层量和有来源/目的地的数据流计搬运。任务关闭不产生该任务的输入传输；任务产物汇集、成品迁往存储位置和客户交付分别计费。
- 为已有资产和每笔新增采购分别记账。折旧在规定年限结束，累计不超过账面金额；原值、现金流和折旧不混用。已有容量不再次采购。
- 补入最低保存期不足费用、低频读取、归档恢复与临时副本；同云交付免流量不代表免读取费用；云上寄盘计到本地的搬运。
- CPU 系数只代表完整 GPU 实例之外的独立核时；云和 IDC 都显式考虑有效 GPU 利用率。默认计算重试开销为 0，代表未估计，而非保证没有重试。
- GB/GiB 明确转换；缺失报价不当作 0。腾讯归档参考修为 0.033，补回百度，火山仅保留标准 0.099 算例，其余留空。
- 基线保存参数、价格、模型版本，在当前月份和成本口径重算。策略按钮不再重置业务量或报价。
- 删除不完整成本口径下的“毛利率”；安全文本渲染、数值校验、情景版本校验、移动端和打印视图。

## V2 的刻意简化

五个主输入：每日采集小时数、原始数据保留、可交付数据保留、每月交付小时数、计算负荷。原始数据 100% 留存、热缓冲 30 天；采集结构按详细版三种模态等比例缩放。

- A：全部在同一家云的标准档。
- B：原始数据 90 天后转归档、满 1 年转深度归档；可交付数据低频；处理在云上。
- C：机房处理，原始数据在机房保留滚动窗口（由已有容量推算），之后转云上归档、满 1 年转深度归档；可交付数据上传云端低频。

三个方案都用详细版逐日模拟跑 36 个月，因此取回、最低保存期补费、折旧与已有资产口径与详细版一致。追加投资仅覆盖存储和 GPU 服务器。重刷事件本身（取回、临时算力）、多云副本和自动寻优尚未建模。会前前提中可填写已有容量、已有 GPU 和关键预算单价。

## 计算边界（不是完整 TCO）

每天恒定到达率，每月 30 天，增长在月初变化。新增流的库存按日首/日末梯形积分；整天年龄阈值下对均匀流入是精确积分。初始原始数据按已留存库存处理，初始批次用统一年龄表达；交付副本不扣减源库存。

计算任务视为读取新原始数据的任务组，而不是完整 DAG。同地远端输入按同一有序样本子集复用一次；不满足该假设时应增加实际搬运。关闭所有算法不等于关闭独立的成品打包。成品延迟只移动输出时间，不模拟排队。处理历史存量、重跑和全量迁移另行评估。

初始库存视为已位于方案指定地点，因此切换部署是目标布局比较，不包含迁移这些现有数据的历史成本。路径单价要含所有按流量费用，与固定接入费不能重复报价。聚合链路数是共享链路的估计需求，不是已验证的拓扑或 SLA。恢复时间从交付窗口扣除；窗口不足显示不可行。

IDC 按本工作负载预留容量计算；采购余量是 `需求 × (1+余量)`，不是使用率水位。每月按最大所需容量整块采购，采购当月开始摊销；到期继续使用并计运营，不自动替换。独立 CPU 服务器、机房/网络建设、融资、灾备和人员不在硬件追加投资内。计费窗口之后尚未结算的最低保存义务也不包含在累计金额中。

原始对象请求、小对象膨胀、外部平台服务费仍以预算或明确排除项处理；不会声称已经复刻供应商完整账单。默认 GPU/CPU 价格与吞吐不构成任何型号性能承诺。

## 情景与安全

导出 JSON 和参数 URL 包含业务量与报价，Base64 不是加密。只在授权范围分发。导入须具有 `schema: "2.2.0"` 及正确 `kind`，详细版为 `detail`、V2 为 `executive`。旧版没有版本信息的 `#s=` 和旧基线不静默沿用，以免在新公式下误解旧配置。
